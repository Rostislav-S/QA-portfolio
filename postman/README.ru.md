# Postman — TotalShiftLeft REST API (QA Portfolio, Middle)

> Демонстрационная коллекция для sandbox-API TotalShiftLeft. Покрывает полный цикл тестирования: от smoke-проверок до E2E-сценариев с передачей данных между запросами.

## 📂 Содержимое

| Файл | Назначение |
|:---|:---|
| [`TotalShiftLeft REST API — QA Portfolio (Middle).postman_collection.json`](./TotalShiftLeft%20REST%20API%20—%20QA%20Portfolio%20(Middle).postman_collection.json) | Коллекция Postman со всеми запросами и тестами |

## 🚀 Как запускать

1. Импортируйте файл коллекции в Postman.
2. Откройте **Collection Runner**.
3. Запустите коллекцию целиком в **последовательном порядке** — некоторые запросы зависят от переменных, устанавливаемых ранее.
4. Внешнее окружение не требуется: все переменные хранятся на уровне коллекции (вкладка Variables).
5. Укажите актуальный `baseUrl` sandbox-API в переменной коллекции перед запуском.

## 📁 Структура коллекции

| Папка | Назначение | Что демонстрирует |
|:---|:---|:---|
| `01_Smoke` | Проверка доступности ключевых эндпоинтов | Статус-коды, структура ответа, схема пагинации |
| `02_CRUD_Users` | Полный CRUD-цикл: Create → Read → Update → Delete | Генерация данных, передача переменных, валидация UUID, частичное обновление |
| `03_Query_Filtering` | Query-параметры: фильтрация и пагинация | Соответствие ответа фильтрам, логика пагинации |
| `04_Error_Handling` | Негативные сценарии: 500, timeout, невалидный UUID, 404, невалидный product_id | Структура ошибок, утечка стека, уровни валидации |
| `05_Advanced_Scripts` | Глубокая валидация через JSON Schema | Форматы (uuid, email, ISO 8601), enum, уникальность, регулярки |
| `99_Cleanup` | Служебная папка: сброс переменных коллекции | Идемпотентность, `pm.execution.skipRequest()` |

## 🔍 Что проверяется

### Smoke

- Статус 200 и флаг `success = true`
- Наличие массива `data`
- Полная структура пагинации: `total`, `page`, `limit`, `pages`, `hasNext`, `hasPrev`

### CRUD

- Создание пользователя: статус 201, структура ресурса, валидность UUID, соответствие сгенерированным значениям
- Чтение: статус 200, полнота и типы полей, совпадение `id` с запрошенным
- Обновление: статус 200, изменение только целевого поля, остальные поля не тронуты
- Удаление: статус 204, пустое тело ответа

### Query-параметры

- Фильтрация: все товары в ответе соответствуют категории
- Пагинация: `page`, `limit`, `hasPrev`, `hasNext` отражают запрошенные значения
- Количество элементов не превышает `limit`

### Обработка ошибок

- **4.1 GET /users?error=500** — серверная ошибка: структура тела ошибки, отсутствие утечки стека
- **4.2 GET /users?delay=2000** — задержка: `responseTime` действительно превышает порог, статус 200 после задержки
- **4.3 GET /users/999999** — невалидный UUID: статус 400, структура ошибки Fastify (`FST_ERR_VALIDATION`), сообщение указывает на UUID
- **4.4 GET /users/{uuid}** — несуществующий ресурс с валидным UUID: статус 404, сообщение об ошибке
- **4.5 POST /orders** — невалидный `product_id` в теле: статус 400, сообщение указывает на `product_id` и формат uuid, отсутствие утечки стека

### Продвинутые скрипты

- Валидация полной схемы ответа через `pm.response.to.have.jsonSchema()`
- Проверка форматов: `uuid`, `email`, ISO 8601 (`date-time`)
- Проверка `role` на вхождение в enum `[user, admin]`
- Уникальность `id` в рамках страницы
- Количество элементов не превышает `limit`

## 🛠️ Ключевые техники

- **Динамические данные:** pre-request скрипты генерируют уникальные имя и email на основе `Date.now()` — коллекция идемпотентна при повторных прогонах
- **Передача переменных:** `userId` создаётся в POST и используется в GET/PATCH/DELETE; защита через `throw new Error`, если переменная не установлена
- **JSON Schema:** глубокая валидация структуры ответа, форматов и enum-значений
- **Негативное тестирование на разных уровнях:** роутинг → бизнес-логика — запросы 4.3 и 4.5 демонстрируют, что невалидный вход отсекается до бизнес-логики
- **Тесты уровня коллекции:** Content-Type, время ответа, наличие флага `success` — применяются ко всем запросам автоматически
- **Идемпотентность:** папка `99_Cleanup` через `pm.execution.skipRequest()` сбрасывает переменные без сетевого вызова
