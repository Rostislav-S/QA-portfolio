### 📡 Postman

Демонстрационная коллекция для sandbox-API **TotalShiftLeft REST API**, оформленная как портфолио Middle API Test Engineer. Покрывает полный цикл тестирования: от smoke-проверок до E2E-сценариев с передачей данных между запросами.

**Структура коллекции:**

| Папка | Назначение | Что демонстрирует |
|:---|:---|:---|
| `01_Smoke` | Проверка доступности ключевых эндпоинтов | Статус-коды, структура ответа, схема пагинации |
| `02_CRUD_Users` | Полный CRUD-цикл: Create → Read → Update → Delete | Генерация данных, передача переменных, валидация UUID, частичное обновление |
| `03_Query_Filtering` | Query-параметры: фильтрация и пагинация | Соответствие ответа фильтрам, логика пагинации |
| `04_Error_Handling` | Негативные сценарии: 500, timeout, невалидный UUID, 404, 403 | Структура ошибок, утечка стека, уровни валидации |
| `05_Advanced_Scripts` | Глубокая валидация через JSON Schema | Форматы (uuid, email, ISO 8601), enum, уникальность, регулярки |
| `99_Cleanup` | Служебная папка: сброс переменных коллекции | Идемпотентность, `pm.execution.skipRequest()` |

**Ключевые техники:**

- Pre-request скрипты для динамической генерации тестовых данных (уникальные имя и email на основе `Date.now()`)
- Передача переменных между запросами (`userId` создаётся в POST, используется в GET/PATCH/DELETE)
- Валидация JSON Schema через `pm.response.to.have.jsonSchema()`
- Негативное тестирование на разных уровнях: роутинг → бизнес-логика → авторизация
- Тесты уровня коллекции: Content-Type, время ответа, наличие флага `success`
- Идемпотентность: папка Cleanup сбрасывает состояние — коллекцию можно прогонять повторно без ручной очистки

- [`TotalShiftLeft REST API — QA Portfolio (Middle).postman_collection.json`](./postman/TotalShiftLeft%20REST%20API%20—%20QA%20Portfolio%20(Middle).postman_collection.json) — файл коллекции
- [`README.ru.md`](./postman/README.ru.md) — подробный разбор структуры коллекции и логики тестов
