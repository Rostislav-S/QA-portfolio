Тестирую на всех слоях: фронтенд (UI/UX, адаптивность, кроссбраузерность), бэкенд (REST API, валидация данных, обработка ошибок) и мобильные приложения. Работаю с распределённой системой из нескольких микросервисов: авторизация и управление пользователями, админ-панель для врачей, интеграция с мобильными приложениями, внешние сервисы расписания и записи к врачам.

Имею практический опыт с Kafka: тестировал отправку СМС, push и email через очереди сообщений, проверял формирование, маршрутизацию и доставку в разных бизнес-сценариях. Для мониторинга использую Lens (поды, логи), Grafana (Loki, Tempo, Prometheus) и Sentry (ошибки в проде), а также Charles Proxy и Chrome DevTools для анализа трафика и отладки.

Предыдущие 12 лет управления сложными техническими системами в нефтегазе научили меня структурировать процессы, быстро разбираться в новой архитектуре и выявлять риски и неоднозначности на этапе анализа требований.

Сейчас развиваюсь в направлении тестирования API и интеграций, а также применяю AI-инструменты для оптимизации рабочих процессов (в рамках политик ИБ).

- [`README.ru.md`](./sql/README.ru.md) — обзор раздела SQL, схема таблиц и демонстрируемые навыки

### 📡 Postman

Демонстрационная коллекция для sandbox-API **TotalShiftLeft REST API**, оформленная как портфолио Middle API Test Engineer. Покрывает полный цикл тестирования: от smoke-проверок до E2E-сценариев с передачей данных между запросами.

**Структура коллекции:**

| Папка | Назначение | Что демонстрирует |
|:---|:---|:---|
| `01_Smoke` | Проверка доступности ключевых эндпоинтов | Статус-коды, структура ответа, схема пагинации |
| `02_CRUD_Users` | Полный CRUD-цикл: Create → Read → Update → Delete | Генерация данных, передача переменных, валидация UUID, частичное обновление |
| `03_Query_Filtering` | Query-параметры: фильтрация и пагинация | Соответствие ответа фильтрам, логика пагинации |
| `04_Error_Handling` | Негативные сценарии: 500, timeout, невалидный UUID, 404, невалидный product_id | Структура ошибок, утечка стека, уровни валидации (роутинг → бизнес-логика) |
| `05_Advanced_Scripts` | Глубокая валидация через JSON Schema | Форматы (uuid, email, ISO 8601), enum, уникальность, регулярки |
| `99_Cleanup` | Служебная папка: сброс переменных коллекции | Идемпотентность, `pm.execution.skipRequest()` |

**Ключевые техники:**

- Pre-request скрипты для динамической генерации тестовых данных (уникальные имя и email на основе `Date.now()`)
- Передача переменных между запросами (`userId` создаётся в POST, используется в GET/PATCH/DELETE)
- Валидация JSON Schema через `pm.response.to.have.jsonSchema()`
- Негативное тестирование на разных уровнях: роутинг → бизнес-логика
- Тесты уровня коллекции: Content-Type, время ответа, наличие флага `success`
- Идемпотентность: папка Cleanup сбрасывает состояние — коллекцию можно прогонять повторно без ручной очистки

- [`TotalShiftLeft REST API — QA Portfolio (Middle).postman_collection.json`](./postman/TotalShiftLeft%20REST%20API%20—%20QA%20Portfolio%20(Middle).postman_collection.json) — файл коллекции
- [`README.ru.md`](./postman/README.ru.md) — подробный разбор структуры коллекции и логики тестов

### 🐍 Python API

Автотесты на Python для того же TotalShiftLeft REST API, написанные на pytest и requests. Проект повторяет структуру Postman-коллекции 1:1 — те же сценарии, но в виде автоматизированных тестов.

**Покрытие (14 тестов):**

| Модуль | Назначение | Тестов |
|:---|:---|:---|
| `test_01_smoke.py` | Проверка доступности ключевых эндпоинтов | 2 |
| `test_02_crud_users.py` | Полный CRUD-цикл с фикстурой `created_user` | 4 |
| `test_03_query_filtering.py` | Фильтрация и пагинация через query-параметры | 2 |
| `test_04_error_handling.py` | Негативные сценарии: 500, timeout, невалидный UUID, 404, невалидный product_id | 5 |
| `test_05_advanced.py` | Глубокая валидация через JSON Schema | 1 |

**Ключевые техники:**

- Фикстура `requests.Session` для общих заголовков и базового URL
- Фикстура `created_user` с `yield` для изоляции setup/teardown
- Валидация JSON Schema через `jsonschema.validate()`, схемы хранятся отдельно в `schemas/`
- Маркеры pytest (`smoke`, `crud`, `query`, `error`, `advanced`) для запуска подмножеств
- HTML-отчёты через `pytest-html`

- [`tests/`](./python_api/tests/) — модули тестов
- [`README.ru.md`](./python_api/README.ru.md) — подробный разбор структуры проекта, покрытия и истории отладки

## 📌 Как использовать это портфолио

1. Выберите интересующую директорию (например, `sql/`, `postman/` или `python_api/`)
2. Изучите README внутри директории — там описано, что демонстрирует каждый артефакт
3. Для запуска Postman-коллекции: импортируйте `*.postman_collection.json` в Postman и запустите через Collection Runner в последовательном порядке
4. Для запуска Python-тестов: следуйте инструкциям в `python_api/README.ru.md`
